## Confirmed problem and change

The real 0.1.10 MCP checks on localhost-0a22 passed screenshot, click, drag and scroll. Its single ASCII text operation received a bridge refusal. A bounded exact-nonce inspection found resultCode 21, focus_changed, with com.topjohnwu.magisk as expected_package even though the captured target was the bundled ProbeActivity. The editor remained empty and the original input methods were restored. The later Android probe had replaced the screenshot application's identity with a transient su-manager observation.

Version 0.1.11 carries the captured application identity through both pre-action inspection and the native action. Android cannot select a different text target from a later probe. Inside the actual privileged shell, after su returns, a bounded foreground check requires two consecutive observations of the same default-display component. It permits at most four read-only observations; unknown, conflicting, duplicate-default or persistently different targets stop before input. Short and full Android component spellings are normalized without changing the target. Text also checks the target again after selecting the temporary IME and before committing.

Bridge acknowledgements now retain only an exact-nonce result from the bundled bridge's finite code/status mapping. Native output and payloads are not copied into errors. A refusal or uncertain result is never automatically replayed. A proven pre-input refusal does not trigger an unnecessary IME mutation; otherwise the existing bounded cleanup remains in force.

The signed bridge APK, Java implementation and manifest were not changed. The installed bridge remains version 0.1.0, SHA256 3159ff9b0e654b4c0d5fbea4cdc9ac568f4ed136c114f0171c8760f030432636. No su policies or Android permission settings were changed.
